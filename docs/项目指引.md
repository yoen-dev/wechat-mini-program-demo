## 1. 项目概览

一个「三角洲行动」游戏**护航下单**的微信小程序。老板（玩家）在小程序里选单子、下单付款，客服派单或老板指定护航，护航打完提交战绩截图，老板确认完成后护航拿到分成。员工（护航、客服、管理员、负责人）也在**同一个小程序**里工作，用管理员发放的账号密码登录后自动进入各自的界面。

| 部分 | 技术 | 位置 |
| --- | --- | --- |
| 前端（小程序 + 网页预览版） | uni-app（Vue 3），一套代码编译成微信小程序和网页 | 根目录 `src/` |
| 后端 | Node.js 20 + Express 4 + knex（数据库工具） | `server/` |
| 数据库 | MySQL 8（云托管自带 MySQL） | — |
| 部署 | 微信云托管（Docker 容器） | `server/Dockerfile` |
| 网页预览 | GitHub Pages（推送到 main 自动部署，用本地模拟数据） | `.github/workflows/pages.yml` |

**两种运行模式**（前端打包时选择，页面代码完全一样）：

- **演示模式（mock）**：不连后端，数据存在手机 / 浏览器本地，用于给别人看效果。GitHub Pages 上的预览就是这个模式。
- **真实模式（cloud / http）**：连接后端。正式小程序用 `cloud`（微信云托管），本地联调用 `http`。

## 2. 整体架构

```
┌──────────── 微信小程序（src/）────────────┐
│  页面 pages/*.vue                         │
│     │  import { listOrders } from '@api/orders.js'
│     ▼                                     │
│  @api 别名（vite.config.js 决定指向哪）     │
│     ├─ src/api/mock/   演示：本地假数据     │
│     └─ src/api/remote/ 真实：请求后端       │
│              │ request.js                 │
└──────────────┼────────────────────────────┘
               │ wx.cloud.callContainer（不需要域名和备案，自动带 openid）
               ▼
┌──────────── 微信云托管（server/）──────────┐
│  app.js  → 中间件（安全头 / 登录解析）       │
│          → routes/*.js   各功能接口         │
│          → services/*.js 业务逻辑 / 微信对接 │
│  jobs/autoConfirm.js 超时自动确认           │
└──────────────┼────────────────────────────┘
               ▼
          云托管 MySQL        云托管对象存储（截图、轮播图）
```

关键设计：

- **页面不知道后端是真是假**。`src/api/mock/xxx.js` 和 `src/api/remote/xxx.js` 导出完全相同的函数名和参数，页面只写 `@api/xxx.js`，打包时由 `vite.config.js` 换成其中一套。
- **钱和状态以后端为准**。下单金额由后端按单子价格和规格重新计算，不信任前端传的金额；所有状态变化都是「有条件更新」（只有在旧状态正确时才改），防止并发出错。
- **登录**：后端发 JWT 令牌，前端存在本地，每次请求放在 `Authorization` 头里。改密码 / 重置密码 / 停用账号会让旧令牌立即失效。

## 3. 五种身份与权限

| 身份 | 代码里的 role | 怎么登录 | 进入哪个页面 | 能做什么 |
| --- | --- | --- | --- | --- |
| 老板（用户） | `user` | 微信登录（首次绑定手机）或手机号 + 验证码 | 首页 `pages/index/index` | 下单、支付、充值、领券、订单沟通、确认完成、评价、退款、售后、报名护航 |
| 护航 | `escort` | 账号密码 | `pages/staff/escort` | 接单开关、抢单、接 / 拒指定单、开始、提交完成（传截图）、收入、提现、编辑资料 |
| 客服 | `cs` | 账号密码 | `pages/staff/cs` | 派单 / 改派、退款审核、售后工单、护航报名审核、用户管理（拉黑） |
| 管理员 | `admin` | 账号密码 | `pages/staff/admin` | **客服的全部权限** + 单子、轮播图、优惠券、员工账号、提现审批、系统设置、操作日志、经营数据 |
| 负责人 | `owner` | 账号密码 | `pages/staff/owner` | **只看不改**：经营数据（流水、用户、单子、护航、客服、储值） |

- 员工账号只能由管理员在「管理后台 → 员工账号」创建；护航报名审核通过时会自动开号。
- 后端权限控制在每个接口的 `need('角色', ...)` 里（`server/src/middleware/auth.js`），前端页面的 `guard([...])` 只是跳转用，真正的拦截在后端。

## 4. 核心业务规则

### 4.1 订单状态流转

```
待付款 ──支付──▶ 待派单（客服派单）/ 待接单（指定护航）
待派单 ──客服派单 / 护航抢单──▶ 已接单
待接单 ──护航接单──▶ 已接单          ──护航拒单──▶ 待派单
已接单 ──护航开始──▶ 进行中 ──护航提交完成（附战绩截图）──▶ 待确认
待确认 ──老板确认 / 超时自动确认──▶ 已完成（护航分成此时入账）
待确认 ──老板点「还没完成」──▶ 进行中
待派单 / 待接单 / 已接单 ──老板申请退款──▶ 退款中 ──同意──▶ 已退款（拒绝则回到原状态）
待付款 ──老板取消──▶ 已取消
```

- 代码：后端 `server/src/services/orderService.js`（规则）+ `server/src/routes/orders.js`（接口）；前端各身份能看到哪些按钮在 `src/orderActions.js`。
- **自动确认**：护航提交后，老板超过 N 小时（默认 24，管理后台可改，0 = 关闭）没确认，系统自动确认。后端每分钟检查一次；云托管实例缩到 0 时，有人查订单也会顺便检查。
- **护航分成** = 实付金额 × 分成比例（默认 70%），在订单「已完成」那一刻按当时的比例写入，之后改比例不影响已完成的订单。
- **并发保护**：两个护航同时抢一单，只有一个成功，另一个提示「手慢了」；重复点支付、重复确认都不会重复处理。

### 4.2 支付与退款

- **微信支付**：后端创建支付 → 小程序弹出微信付款 → 微信回调后端 → 订单变为已支付。前端付完后还会主动请后端查一次结果（回调可能慢几秒）。
- **余额支付**：扣余额和改订单状态在同一个数据库事务里，要么都成功要么都不做；余额不足会提示。
- **退款**：
  - 余额支付的订单：同意退款后**自动退回余额**。
  - 微信支付的订单：目前同意退款后，需要**在微信支付商户平台手动退款**（以后可以接入自动退款接口，见第 12 节）。

### 4.3 储值充值

- 管理员设置充值档位（默认：100、300 送 20、500 送 50、1000 送 120）。
- 充值走微信支付，**付款成功后才到账**（实付 + 赠送）。
- 首页「某某刚刚充值」提示只显示**真实**的充值记录（最近 48 小时、达到最低金额、名字打码），可以在后台关闭。不要做虚假的充值弹窗，这属于虚假宣传。
- 统计口径：充值是预收款，老板用余额下单时才计入成交额；「用户余额总额」是公司欠用户的钱。

### 4.4 优惠券

管理员建券（减免金额、满多少可用、领取后有效几天）→ 老板领取（每种券每人一张）→ 下单时自动选减得最多的一张 → **支付成功时才标记为已用**（只下单不付款不会浪费券）。退款不退券。

### 4.5 提现

护航可提现 = 已完成订单分成总和 − 已打款 − 审核中。护航申请 → 管理员**线下转账**后点「已打款」（或驳回）。同时提交两次也不会超额（后端加了行锁）。

## 10. 部署到微信云托管

### 10.1 前提（需要公司来办）

1. **注册小程序**（企业主体），拿到 **AppID**。个人主体的小程序不能开通微信支付。
2. 小程序**备案**（新小程序上线前必须做，在小程序后台「设置 → 基本设置 → 备案」）。用云托管就**不需要**再给域名做 ICP 备案。
3. 要收钱的话：**开通微信支付商户号**（企业资料，审核几天），并在商户平台「产品中心 → AppID 账号管理」关联小程序 AppID。
4. 要用手机号登录的话：开通阿里云短信（签名和模板需要审核）。

### 10.2 开通云托管和数据库

1. 打开 [微信云托管控制台](https://cloud.weixin.qq.com/cloudrun)，用小程序管理员微信扫码登录，选择小程序，**新建环境**（记下环境 ID，形如 `prod-xxxx`）。
2. 在环境里开通 **MySQL**（选最低配置即可起步）。开通后云托管会自动把连接信息注入给服务，**不用手动建库**（启动时自动创建）。

### 10.3 部署后端

1. **新建服务**，服务名称填 `api`（如果改名，`.env.cloud` 的 `VITE_CLOUD_SERVICE` 和环境变量 `CLOUD_SERVICE` 都要一起改）。
2. **发布版本**：选择「代码库」绑定 GitHub 仓库并把**目录**设为 `server`（会按 `server/Dockerfile` 构建），或者把 `server` 文件夹打包上传。端口填 **80**。
3. **服务设置 → 环境变量**，至少填：

   ```
   DB_NAME=escort
   JWT_SECRET=（一长串随机字符）
   ADMIN_INIT_PASSWORD=（第一个管理员的初始密码）
   WX_CLOUD=true
   WX_MOCK=false
   SMS_MOCK=true        # 短信接好前先保持 true
   PAY_MOCK=true        # 支付接好前先保持 true
   ALLOW_UNSAFE_PROD=true   # 只要上面还有 MOCK=true 就必须加这一行才能启动；全部接好后删掉
   CLOUD_ENV=prod-xxxx
   CLOUD_SERVICE=api
   ```

4. **服务设置 → 公网访问：关闭**（重要！小程序走内部调用不需要公网；开着的话外部可以伪造 openid 请求头）。
5. 实例数：最小 0（没人用时不收计算费，第一次访问会慢几秒）或最小 1（一直在线，响应快）。可以先 0，用户多了再改。
6. 看「日志」：出现 `[启动] 后端已运行` 就成功了；第一次启动还会打印创建管理员的信息。

### 10.4 打包上传小程序

1. `src/manifest.json` 里 `mp-weixin.appid` 填 AppID。
2. `.env.cloud` 里填 `VITE_CLOUD_ENV`（环境 ID）。
3. `npm run build:mp-weixin:cloud`，用微信开发者工具打开 `dist/build/mp-weixin`，预览测试 → 上传 → 小程序后台提交审核。
4. 正式包里登录页不会显示演示账号，也不会出现「模拟微信支付」弹窗。

### 10.5 接入短信和支付（拿到资质后）

- **短信**：阿里云短信申请签名和验证码模板（模板变量叫 `code`），在环境变量填 `SMS_ACCESS_KEY_ID`、`SMS_ACCESS_KEY_SECRET`、`SMS_SIGN_NAME`、`SMS_TEMPLATE_CODE`，`SMS_MOCK=false`。也可以只保留微信登录 + 绑定手机号，把手机号登录去掉。
- **支付**：云托管控制台「设置 → 其他设置 → 微信支付配置」绑定商户号并在商户平台确认授权；环境变量填 `WXPAY_MCHID`、`PAY_MODE=cloud`、`PAY_MOCK=false`。
- 全部接好后删掉 `ALLOW_UNSAFE_PROD`，重新发布。

> ⚠️ 短信和支付的正式代码在拿到资质前**无法实测**。上线前一定要用自己的手机号收一次验证码，用 0.01 元的单子把「下单 → 付款 → 订单变待派单」和「充值 → 到账」各走一遍。如果云托管接口有变化，按 `server/src/services/pay.js` 顶部的文档链接对照修改。

## 13. 常见问题

**Q：GitHub Pages 上的网页预览会连到正式后端吗？**
不会。网页预览一直是演示模式（本地假数据），和正式数据完全隔离。

**Q：改了代码怎么更新线上？**
后端：推送代码后在云托管「发布版本」（绑定代码库的话可以设置自动发布）。数据库结构变化会在启动时自动升级。前端：重新 `npm run build:mp-weixin:cloud` → 上传 → 提交审核。

**Q：管理员密码忘了怎么办？**
让其他管理员在「员工账号」里重置。如果唯一的管理员也忘了：在云托管 MySQL 管理界面把这个账号的 `role` 临时改掉，再重启服务（数据库里没有管理员时会按 `ADMIN_ACCOUNT` / `ADMIN_INIT_PASSWORD` 新建一个），登录后再改回来。

**Q：老板用手机号登录的，为什么不能微信支付？**
微信支付需要 openid，只有通过微信登录的账号才有。可以用余额支付，或者退出后用微信登录（绑定同一个手机号会提示已被占用，需要客服处理合并）。建议正式上线时以**微信登录为主**。

**Q：云托管第一次打开很慢？**
最小实例数为 0 时，没人访问会缩容，第一次访问要启动容器（几秒）。把最小实例数改成 1 即可，代价是一直计费。

**Q：经营数据会不会越来越慢？**
现在是读出时间段内的订单再统计，每天几百单以内没问题。数据很大时可以改成 SQL 汇总或每天预先算好存一张统计表（`server/src/routes/analytics.js`）。

**Q：怎么确认后端改动没把别的功能弄坏？**
`cd server && npm test`，25 项测试覆盖了主要流程。新增功能时最好在 `server/test/api.test.js` 里补一条测试。
